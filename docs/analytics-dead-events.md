# Мёртвые события портфолио: разбор нулей (2026-10-18)

Разбор тайла **«Ожидаемые, но мёртвые события (90д)»** (дашборд
[05 · Здоровье аналитики](https://us.posthog.com/project/451732/dashboard/2226422)).
Детектор нашёл **32 из 54 объявленных событий с нулём строк за 90 дней**. Этот
документ отвечает на вопрос, который детектор не задаёт: **нуль — это сломанная
инструментация или отсутствие трафика?**

- Метод: HogQL по `events`, окно 90 дней (до 2026-10-18), плюс `$autocapture`
  как независимый счётчик кликов — если клики на странице есть, а наших событий
  нет, это сломанная разметка; если нет ни одного клика, событие не могло
  наступить.
- Источник имён: `AnalyticsEventMap` + `docs/analytics-events.md` §1–§2 +
  игровой бандл (см. `expected_events()` в `monitoring/dashboards/create_dashboards.py`).

## Главный вывод

**30 из 32 нулей — следствие трафика, а не аналитики.** Страницы, где живут эти
события, за 90 дней посмотрели 2–22 уникальных посетителя, и кликов на них
почти нет. При такой базе любое событие с вероятностью <1% на визит даёт 0–2
строки за квартал — нуль ожидаем и ничего не говорит о коде.

Недельные уникальные посетители за тот же период: 5, 6, 7, 5, **27, 41**, 16,
10, **140, 70** (два всплеска в октябре — внешние: рассылка/репост/боты).
Обычная неделя — 5–27 человек на весь сайт.

## Правило объёма (чтобы не повторять)

При текущем трафике тайл можно считать осмысленным, только если ожидаемый
объём события ≥10 строк / 90 дней. Всё, что реже, обязано быть помечено
«ожидаемо пусто» — иначе дашборд превращается в стену нулей, а владелец
перестаёт ему верить. Так уже помечены: «Поиск: попадания и пустые»
(дашборд 03) и «CTA rail: экспозиция → клик» (дашборд 04, до деплоя).

## Что делать (по приоритету)

1. **Трафик, а не события.** Инструментация уже избыточна: 54 объявленных
   события на 5–27 уникальных в неделю. Новые события не добавлять.
2. **Работать с 5 страницами, где есть люди**: `/` (364+631 pv), `/projects/`
   (147), `/graph/` (122), `/writing/` (100), `/about/` (92). Смотреть, что на
   них кликают (`$autocapture`), и улучшать именно это. `/contact/`,
   `/library/`, `/colleague/` — по 10–65 pv и ~0 кликов: либо менять их роль,
   либо перестать считать их каналами.
   Наблюдение по `/projects/`: чипы **стека** (Python/SQL/Tableau/GitHub) за 90
   дней кликнули 13 раз, табы **категорий** (`projects_track_filter`) — ни
   разу. Категории не работают; фильтр по стеку работает.
3. **Решения по двум аномалиям** (не технические, а продуктовые):
   - поиск: 213 страниц, 305 уникальных, 0 открытий за всё время → не
     развивать; при желании убрать кнопку из nav, чтобы не занимала место;
   - форма контакта: либо включить (`PROJECT_REF` в `src/lib/contact.ts`),
     либо удалить `contact_submit` / `contact_form_error` из карты и доков.
4. **Игры**: после деплоя (общий `distinct_id`) проверить `game_selected` за
   неделю. Если рост не появится — проблема в том, что в игры не заходят.

## Как перепроверить

```bash
cd monitoring/dashboards && set -a && source ../.env && set +a
python3 create_dashboards.py --only v2 --apply   # re-syncs the detector tile
python3 verify_dashboards.py                     # every tile's query vs live data
```

Числа трафика и кликов — те же HogQL-запросы, что использовались при разборе:
`$pageview` / `$autocapture` по `properties.$pathname` за 90 дней.
