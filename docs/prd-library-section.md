## 2. Решения владельца

Зафиксировано в дизайн-сессии 2026-10-06. Каждое — выбор против альтернативы.

| # | Решение | Отвергнуто и почему |
|---|---|---|
| 1 | Job-to-be-done: **сигнал глубины**, SEO/трафик — побочный эффект | «Витрина полноты» — нулевой сигнал: вписать Kohavi может любой. «Ведёт к контакту» — не работа отдельного раздела |
| 2 | Запись: **гибрид** — карточка обязательна, тело опционально | Только карточка игнорирует уже написанные тела. Только эссе — стоп-фактор наполнения (сейчас 2 записи) |
| 3 | Состав: **книги + курсы + статьи + доклады**, поле `kind` | «Только книги» теряет гант-доклад и статью про CUPED при равном сигнале. «Всё включая видео» размывает раздел |
| 4 | Масштаб: **10–12 записей**, потолок 12 | 15–30 требует пагинации; 50+ — это отдельный продукт с мотивацией вести лог |
| 5 | Связность: **обратные ссылки на источники + поиск/LLM**; узел в графе — позже | Граф уже плотный, 10 записей не изменят топологию |
| 6 | EN: **карточка обязательна, тело — только RU**. Контент правится руками в репо | Полный перевод тел не окупается при partial-EN (нет `en/writing`, `en/contact`). Автосинк из Z-core создаст второй источник правды |
| 7 | **Ячейка библиотеки возвращается на главную** (3 плитки) | Оставить раздел за одним пунктом меню — сигнал из решения 1 не доходит |
| 8 | Тело живёт **на отдельной странице** `/library/<slug>/` + EN | Раскрытие на месте (`<details>`) и «простыня под сеткой» не дают URL → тело не шарится, не индексируется, решение 5 вырождается |
| 9 | Словарь: **`kind` + `status` — enum'ы, поле `tag` удаляется** | Свободный `tag` нетипизирован и дрейфует. `kind`+ручной override оставляет вторую метку без инварианта |
| 10 | **`href` удаляется, вводится `url`** — абсолютная ссылка на источник, обязательна для `kind=paper\|talk` | `href` смешивал «куда ведёт плитка» и «где источник». Внутренние «куда посмотреть» заменяются вычисленными обратными ссылками (решение 5) |
| 11 | `status` = **`reading \| reference \| done`** (3 значения) | `queued` («хочу прочитать») ослабляет сигнал: непрочитанное в одном списке с прочитанным |
| 12 | Индекс `/library/` — **сетка**, уходит из `container-content`; страницы источников остаются в прозовой колонке | Сетка карточек в 65ch-колонке читается тесно |

## 3. Архитектура

```
src/content/library/**.md         src/content/library-en/**.md
   (kind, status, url, order)         (зеркало; slug-паритет обязателен)
              │                                   │
              └──────────┬────────────────────────┘
                         ▼
          src/lib/library.ts   loadSources(lang)      ← обход питфолла «getStaticPaths
                         │                                не видит frontmatter»
         ┌───────────────┼────────────────┬──────────────────────┐
         ▼               ▼                ▼                      ▼
  ReadingBlock      library/[slug].astro  index.astro       (v2) sources[]
  (индекс +         (тело, container-    (ячейка бенто,    в frontmatter
   главная)          content)            3 плитки)         проектов
                                                              │
                                                              ▼
                                                    вычисленные «Применил в»
                                                       на странице источника
```

Ключевые решения и почему:

- **Один источник правды на связь «источник ↔ проект».** Связь хранится в frontmatter **проекта** (`sources: [slug]`), обратные ссылки на странице источника **вычисляются**. Иначе одна связь живёт в двух файлах и разъезжается при правке одной стороны.
- **`getStaticPaths` не видит frontmatter** (питфолл репо, `docs/` и `reference-astro-pitfalls`): данные обязаны приходить из `src/lib/`, а не из `Astro.props` фронтматтера — отсюда `src/lib/library.ts`, по образцу `src/lib/posts.ts`.
- **`withBase()` на всех внутренних ссылках** — жёсткое правило репо (`CLAUDE.md:285-294`). Плитка источника ведёт на вычисленный путь `${isEn ? 'en/' : ''}library/${slug}/`, резолвится через `withBase`.
- **Locale containment — инвариант, а не стиль.** EN-плитка никогда не должна уводить в RU-ветку. Гейт существует на двух уровнях (источник + собранный `dist/`) и переживает редизайн, потому что проверяет разрешимость URL внутри локали, а не способ его хранения.

## 7. Приёмка

Позитивный путь:

1. `bun run build` — сборка зелёная, страниц больше, чем 135.
2. На `/library/` — сетка; клик по плитке ведёт на страницу источника внутри RU-ветки; `url` открывает внешний источник в новой вкладке.
3. На `/en/library/` то же самое, и ни одна ссылка не уводит в RU.
4. На главной видна ячейка с тремя плитками, ссылка «Все источники →».
5. События `library_tile` и `bento_library` уходят в PostHog.
6. `bun run check && make check` — зелёный.

Негативные кейсы:

- Добавить `kind: "bloG"` → `bun run build` **падает** на схеме (REQ-LIB-01).
- Добавить `kind: talk` без `url` → сборка падает (REQ-LIB-02).
- Добавить источник только в `library/`, без EN-близнеца → падает тест slug-паритета.
- Вписать в EN-файл `url: "library/foo/"` → падает проверка абсолютного URL.

- Пагинацию и фильтр по `kind` — до порога 12 записей незачем.
