# Feedback 360 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Страница `/feedback/` на сайте и Edge Function, принимающая анонимные структурированные отзывы от HR, менеджеров и коллег в Supabase, с приглашениями по токену и выгрузкой в файл.

**Architecture:** Статичная Astro-страница с нативной `<form method="post">`; вопросы и лимиты — типизированный контракт в `src/lib/feedback.ts`; Edge Function `feedback` (Deno, скелет `ingest`) нормализует JSON и urlencoded, проверяет honeypot, лимит по `ip_hash` и токен приглашения, пишет через PostgREST под `service_role` в таблицы с RLS без политик. Приглашения создаются и ответы выгружаются локальными скриптами.

**Tech Stack:** Astro 7 static, TypeScript, Bun test, Deno Edge Function, Supabase Postgres/PostgREST, vanilla island script (без фреймворков).

**Spec:** `docs/prd-feedback-360.md`

## Global Constraints

- Новых npm-зависимостей нет. Клиентский JS — только островной `<script>` компонента, никаких фреймворков и внешних скриптов.
- Форма обязана работать без JS: нативный `<form method="post">` + HTML-ответ при `Accept: text/html`.
- Таблицы: `RLS enable` + **ноль политик**; браузер не читает ничего; пишет только `service_role`.
- `feedback_invites.label`, `feedback_responses.ip_hash` и `invite_id` **не попадают** в выгрузку; токен в аналитику не попадает.
- Соль для `ip_hash` — отдельный секрет `FEEDBACK_IP_SALT`; `IP_SALT` из `ingest` не переиспользуется.
- Caps: `task|helps|friction|gap` = 600, `more` = 1000, `signature` = 120. Значения зеркалятся в SQL CHECK, в `src/lib/feedback.ts` и в функции; drift-тест сравнивает три источника.
- Deno-стиль: одинарные кавычки, ширина 120 (`supabase/deno.json`); `deno fmt --check` и `deno lint` обязаны быть зелёными.
- Проза в заметках/PRD — русская; код, имена, комментарии в коде — английский.
- Коммит после каждой задачи; **push не делается** без отдельного разрешения владельца.
- `tests/built/*` требуют `bun run build` до запуска.

## Review Focus

- **Пересланная или испорченная invite-ссылка** — человек прошёл по старой ссылке и ждёт, что отзыв сохранится. Ожидание: ответ принимается как `open`/роль из формы, а не 400. Тест — Task 3.
- **Браузер без JS** — нативная отправка `application/x-www-form-urlencoded` на тот же endpoint, в ответ приходит HTML, а не JSON. Тест — Task 3 (parser) и Task 5 (разметка).
- **Бот заполнил honeypot** — ожидание: 200 без строки в таблице и без сигнала боту. Тест — Task 3.
- **Ответ длиной cap+1 и лишний ключ** — ожидание: 400 с именем поля, остальные поля не обрезаются молча. Тест — Task 3.
- **Токен приглашения в адресной строке** — ожидание: `$current_url` в PostHog не содержит `t=`/`r=`. Тест — Task 4.
- **Потолок лимита за NAT** — 11-й ответ за час с того же `ip_hash` получает 429, при этом три коллеги из одного офиса проходят. Тест — Task 3.
