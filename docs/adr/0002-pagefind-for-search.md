# ADR-0002: Pagefind как движок поиска, собственный индекс — только для фасетного обзора

08.11.2026 поиск в шапке (QuickFind) переведён с самодельного скоринга по
`search-index.json` на [Pagefind](https://pagefind.app) 1.6, который собирает
индекс из готового `dist/` шагом `pagefind --site dist` в `package.json`
`build`. Собственный индекс остаётся, но с одной ролью: ответить «что свежее в
этом типе» при пустом запросе (фасетный обзор) и дать fuzzy-фолбэк по
заголовкам. Раньше `score()` сравнивал запрос только с заголовком, описанием и
тегами записи, поэтому тело поста не находилось вообще: «когорт» не находил
«Когортный анализ удержания».

Статус: accepted

## Considered Options

- **Оставить `score()` и расширить поля.** Пришлось бы держать полные тела
  постов в `search-index.json`, самим писать токенизацию, стемминг для
  русского и подсветку. Каждый пост раздувал бы JSON, который грузится целиком
  на клиенте.
- **FlexSearch / MiniSearch в браузере.** Индекс пришлось бы строить на
  клиенте из того же JSON — та же проблема размера, плюс время построения на
  мобильном.
- **Algolia / Orama Cloud.** Внешний сервис, ключ в статике, зависимость от
  сети и квоты — для сайта на GitHub Pages это лишняя инфраструктура.
- **Pagefind.** Бинарник на этапе сборки, индекс нарезан на чанки и грузится по
  требованию, WASM-поиск в браузере, стемминг RU из коробки, ноль внешних
  сервисов.

## Consequences

- **Индекс — allow-list.** Страница попадает в поиск только если её `<main>`
  несёт `data-pagefind-body`; это ставит проп `searchType` в `Base.astro`.
  Шаблон, забывший проп, молча выпадает из индекса — поэтому есть
  `tests/built/search-quality.test.ts` с золотыми запросами.
- **Два индекса, а не один.** Pagefind разводит RU и EN по `<html lang>`.
  Фильтр `lang` через JS API не работает (в индекс попадал только `ru`),
  поэтому локаль проверяется по URL результата (`/en/`).
- **Навигация вырезана.** `Breadcrumbs` и `InnerTOC` несут
  `data-pagefind-ignore`, иначе хлебные крошки и оглавление попадали в сниппеты
  и в релевантность.
- **Фасеты по типу — фильтр Pagefind (`type`); фасетный обзор без запроса —
  по-прежнему `search-index.json`.** Два источника, но у каждого своя роль:
  Pagefind не умеет «покажи всё».
- **Нет нечёткого поиска** (Pagefind [issue #2](https://github.com/Pagefind/pagefind/issues/2)).
  Опечатки ловит `ldWithin` из `src/lib/fuzzy.ts` по заголовкам — тот же
  фолбэк, что был до миграции.
- **Тихая деградация запрещена.** Если `pagefind.js` не загрузился, `catch`
  пишет `console.error`, а не подменяет выдачу фолбэком незаметно: именно
  проглоченный `ReferenceError` (переменная `pagefindUrl` не читалась из DOM)
  выглядел как «поиск не находит посты», хотя индекс был цел.
- **Аналитика.** Каждый различимый запрос — `search_used` /
  `search_no_results` с `surface` (`header` | `explorer` | `glossary`); клик по
  результату — `search_result_click` с `rank` (1-based). Смена фасета в
  Explorer — `filter_applied`.
