# PRD — Persona-лендинг: выбор пути в портфолио

| Field | Value |

| Owner | Nikita Boyarkin |
| Status | Draft — готов к ревью |
| Скоуп | RU + EN, статический Astro, 3 версии + гейт |
| Связано | `docs/prd-v7-target-roles.md` (кто в аудитории), `docs/analytics-events.md`, `docs/DESIGN.md` |

Цель: превратить корень сайта в **страницу выбора пути** — три версии портфолио под три аудитории,
с запоминанием выбора и переключателем роли.

---

## 1. Проблема

Корень `/` сейчас — один editorial hero (`src/pages/index.astro`, `<section id="intro">`): все 17
проектов сразу, в одном порядке, с одной подачей. Три разные аудитории приходят с разными вопросами:

| Аудитория | Вопрос, на который ищет ответ |
|---|---|
| HR / рекрутер | Формальные признаки: роль, стек, метрики, «дотягивает ли до вакансии». Скачивает CV. |
| Нанимающий менеджер | Impact и решения: какой результат, какие trade-offs, умеет ли думать. |
| Коллега / аналитик | Как сделано: код, данные, метод, граф знаний, техдетали. |

Одна страница обслуживает никого из них хорошо. HR тонет в техдетали, коллега не видит графа и
исходников, менеджеру кейсы с результатом не вынесены наверх.

**Инфраструктура аудитории уже заложена и мертва.** Её надо оживить, а не строить с нуля:

- `src/lib/analytics.ts:240-257` — `registerSuperProperties()` читает `localStorage['audience']`,
  разрешённые значения `'recruiter' | 'analyst' | 'learner'`, дефолт `'recruiter'`.
- `src/components/Base.astro:240-252` — ставит `<html data-audience>` из того же ключа.
- **Ничего этот ключ не пишет**: ни UI, ни вызова `setItem`.
- `src/styles/global.css:357-419` — осиротевший CSS `.audience-bar` / `.audience-note`
  (селектор `#intro + .audience-bar`), разметки под ним нет ни на одной странице.

---

## 2. Цель

1. Корень `/` (`/en/`) = страница выбора пути: 3 карточки + компактный hero.
2. Три статические версии: `/hr/`, `/manager/`, `/colleague/` (и EN-зеркало).
3. Выбор запоминается; на страницах ролей виден переключатель.
4. Выбор трекается в PostHog.
5. Существующие URL (`/projects/`, `/about/`, `/library/`, …) остаются живыми и не ломаются.

---

## 3. Не входит в скоуп

- Контент страниц `about/`, `contact/`, `library/`, `notes/`, `glossary/`, `topics/` — не трогаем.
- Авторизация, аккаунты, серверная/динамическая персонализация сверх 3 статических роутов.
- 4-й роут («показать всё» отдельной страницей) — не заводим, дефолт-ветка = `/colleague/`.
- Новые проекты в коллекции `projects` / `projects-en`.
- Редиректы на основе `localStorage` — не делаем (см. §10, решение Q11).

## 5. Таксономия ролей

| Роль | Значение ключа | Кому | Ветка по умолчанию |
|---|---|---|---|
| HR | `hr` | Рекрутер, HR-скрининг | — |
| Нанимающий менеджер | `manager` | Тот, кто решает по кейсам | — |
| Коллега | `colleague` | Аналитик/разработчик; также дефолт «просто посмотреть» | ✅ |

Старые значения (`recruiter`, `analyst`, `learner`) **удаляются**. `learner` не заводим — дефолт
отдан `colleague`.

Хранилище и инертные механизмы (переиспользуются как есть, меняются только значения):

- `localStorage['audience']` — источник истины на клиенте.
- `<html data-audience="hr|manager|colleague">` — устанавливается из ключа (`Base.astro:240-252`).
- PostHog super-property `audience` — из того же ключа (`analytics.ts:240-257`).

## 7. Курирование: `ROLE_CURATION`

Привязка живёт в одном месте — `src/lib/projects.ts`, рядом с существующими `PROJECT_ORDER` и
`HEADLINE_PROJECTS`:

```ts
// src/lib/projects.ts
export const ROLE_CURATION: Record<'hr' | 'manager' | 'colleague', string[]> = {
  hr:        ['volta', 'sql', 'cohort', /* 5–6 всего */],
  manager:   ['volta', 'sql', 'cohort', 'rfm', /* 8–10 всего */],
  colleague: ['*'],   // '*' = все 17 по PROJECT_ORDER
};
```

- `colleague` = `'*'` → `PROJECT_ORDER` целиком, без перечисления.
- Слаги — те же, что в `PROJECT_ORDER` (17); список `hr`/`manager` — подмножества, порядок внутри
  подмножества = порядок отображения на странице роли.
- Ошибка сборки при неизвестном слаге — предпочтительно (типизировать ключи), чтобы опечатка не
  тихо теряла проект.

## 9. Гейт (`PersonaGate`) — `/` и `/en/`

Состав сверху вниз:

1. **Компактный hero**: имя, «Продуктовый аналитик», одна строка (PhD / фокус A/B+retention).
   Без bento и без фичер-карты `volta` — они уезжают в `/colleague/`.
2. **Три карточки** — HR / Нанимающий менеджер / Коллега. Каждая: заголовок, одна строка «что здесь
   найдёшь», ссылка на `/<role>/`. Вся карточка — кликабельная ссылка.
3. **Вторичная ссылка** «показать всё →» → `/colleague/` (Q14).
4. Подсветка: если в `localStorage['audience']` уже есть роль — её карточка выделена и появляется
   строка «продолжить как HR →».

Поведение: **всегда гейт, без авто-редиректа** (Q11). Статика, без серверной логики.

## 11. Аналитика

Через `track()` из `src/lib/analytics.ts` (никогда напрямую в `posthog`).

| Событие | Когда | Пропсы |
|---|---|---|
| `persona_gate_view` | Показ гейта `/` или `/en/` | `{ lang, has_stored_choice }` |
| `persona_selected` | Клик по карточке гейта **или** переключателю роли | `{ persona, lang, source }` |

`source`: `'gate'` (карточка) \| `'switch'` (переключатель).
Super-property `audience` (из `analytics.ts:240-257`) продолжает регистрироваться после выбора —
дополнительных правок не требует, кроме смены набора значений.

Клик по карточкам — через существующий делегированный `[data-analytics]` хэндлер
(`Analytics.astro:237-250`).

## 13. Критерии приёмки

1. `/` показывает гейт с 3 карточками; клик ведёт в соответствующую версию.
2. Выбор пишется в `localStorage['audience']`; `<html data-audience>` совпадает с выбором.
3. Прямой заход на `/manager/` открывается без редиректа с гейта.
4. Возврат на `/` — снова гейт, выбранная карточка подсвечена, есть «продолжить как …».
5. `/en/*` полностью зеркалит `/` (гейт + 3 версии).
6. PostHog ловит `persona_selected {persona, lang, source}` и `persona_gate_view`.
7. Существующие URL (`/projects/`, `/about/`, `/library/`, `/notes/`, `/glossary/`) работают,
   wikilink-адреса не сломаны, `redirects` в `astro.config.mjs` не затронуты.

| **Lighthouse-бюджет**: у репо есть `.lighthouserc.json` и лимиты | Новые страницы — статические, без новых тяжёлых зависимостей; прогон `lhci` перед мержем |
